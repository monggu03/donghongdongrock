문을 하나씩 통과: 설치 → 린트 → 테스트 → 빌드

문마다 통과해야 다음 문으로, 결과는 실습 레포의 실제 출력

설치: 잠금 파일에 적힌 버전 그대로 패키지 설치

린트: 안 쓰는 변수처럼 실수하기 쉬운 코드 찾기

테스트: 미리 적어 둔 기대값과 실제 결과 비교

빌드: 배포할 파일 만들기, 넷 다 통과하면 머지 가능

검사는 문을 하나씩 지나가는 방식입니다. 문을 통과해야 다음 문으로 갑니다. 화면에 뜨는 결과는 실습 레포에서 실제로 돌린 출력입니다. (클릭) 먼저 설치. 잠금 파일에 적힌 버전 그대로 패키지를 설치합니다. (클릭) 린트. 안 쓰는 변수처럼 실수하기 쉬운 코드를 찾습니다. (클릭) 테스트. 미리 적어 둔 기대값과 실제 결과를 비교합니다. 여섯 개 다 통과. (클릭) 빌드. 실제로 배포할 파일을 만들어 봅니다. 넷 다 초록이면 PR에 초록 체크가 붙고, 머지 문이 열립니다.

이 문들이 돌아가는 곳: 매번 새로 빌리는 컴퓨터

러너: GitHub가 빌려주는 깨끗한 리눅스 컴퓨터

이 검사들은 어디서 돌까요. 제 컴퓨터가 아닙니다. (클릭) GitHub가 빌려주는 깨끗한 리눅스 컴퓨터, 러너에서 돕니다. 실행이 끝나면 버려지기 때문에 매번 설치부터 다시 합니다. 그래서 내 컴퓨터에만 깔려 있던 무언가에 기대는 코드는 여기서 걸립니다. (클릭) 어떤 문을 어떤 순서로 지날지는 레포 안 yml 파일 하나에 적어 둡니다. GitHub Actions는 이 파일을 읽고 러너에서 실행해 주는 서비스입니다. 단계 하나가 아니라 단계 전체를 감싸는 틀입니다.
